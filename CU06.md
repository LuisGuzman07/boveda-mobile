# Usar CU-06 en Android

Mantén el autenticador existente. El botón de carpeta en su barra abre el módulo Bóvedas cifradas. No requiere modificar la web.

1. Aplica la migración del backend descrita en `boveda-backend/CU06.md`.
2. Activa MFA TOTP de tu cuenta desde la web y vincula el QR con el autenticador.
3. Desde esta carpeta:

```powershell
flutter pub get
flutter test test/vault_crypto_test.dart
flutter run --dart-define=BOVEDA_API_URL=http://10.0.2.2:8001/api/v1
```

La URL anterior corresponde al emulador Android. En un teléfono real, usa la IP LAN del PC en lugar de `10.0.2.2`; ambos deben estar en la misma red. Para Windows, usa `http://localhost:8001/api/v1`. El cliente de bóveda tiene configuración propia para no cambiar el servicio de salud del autenticador. Android debug admite HTTP local; en distribución se debe usar HTTPS. No se habilita un comodín de CORS ni se modifica el backend para aceptar todos los orígenes.

4. Abre Bóvedas cifradas e introduce correo, contraseña de cuenta y el TOTP actual. Al ingresar se registra/autoriza este dispositivo mediante el flujo existente de Maikol.
5. Introduce nombre, descripción opcional y una contraseña maestra independiente (mínimo 12 caracteres), y confirma la contraseña.
6. Pulsa Crear bóveda. Ante un fallo de red, Reintentar conserva exactamente el mismo cuerpo cifrado y clave de idempotencia. La solicitud cifrada pendiente se conserva en almacenamiento seguro y se recupera al volver a ingresar, incluso después de cerrar la app.
7. Selecciona la bóveda y vuelve a introducir la contraseña maestra. La aplicación recupera el sobre del servidor y verifica/descifra el nombre y descripción localmente. No carga archivos.

La sesión de bóvedas caduca a los 15 minutos: vuelve a ingresar con un TOTP actual. Revocar la sesión o dispositivo en la web impide nuevas operaciones de bóveda. Cerrar sesión en esta pantalla descarta el token en memoria; no revoca la sesión servidor del flujo existente. Desinstalar la app o borrar su almacenamiento puede destruir el material necesario para abrir las bóvedas. Emergency Kit y acceso desde otro dispositivo no forman parte de CU-06.

Prueba con datos ficticios. No guardes contraseñas maestras en logs, capturas o repositorios. El TOTP del autenticador anterior continúa almacenado como antes; este módulo nuevo no migra sus cuentas.

## Validación y configuración Android

Las pruebas de cifrado y navegación se ejecutan con `flutter test`. El análisis de los archivos nuevos se ejecuta con `flutter analyze lib/services/vault_crypto_service.dart lib/services/vault_api_service.dart lib/screens/vault_screen.dart test/vault_crypto_test.dart test/vault_screen_test.dart`.

La configuración se alineó con la plantilla del Flutter instalado (3.35.4): Gradle 8.12, Android Gradle Plugin 8.9.1 y Kotlin 2.1.0. Se aplica explícitamente `org.jetbrains.kotlin.android` al módulo `app`; los objetivos Java/Kotlin permanecen en 17. Esto reemplaza la combinación anterior de AGP 9.1.0/Kotlin 2.4.0, que fallaba antes de compilar Dart. No se cambian funcionalidades del autenticador ni servicios de los casos de uso anteriores. Las restricciones de las versiones recientes están descritas en la [guía oficial de migración de Flutter](https://docs.flutter.dev/release/breaking-changes/migrate-to-built-in-kotlin/for-app-developers).

Para compilar: `flutter build apk --debug`. Para ejecutar el emulador instalado: `flutter emulators --launch Pixel_7`; después usa `flutter devices` y ejecuta `flutter run -d <id_android> --dart-define=BOVEDA_API_URL=http://10.0.2.2:8001/api/v1`. Mantén el backend iniciado en el puerto 8001. Compilar el APK y ejecutar pruebas automatizadas no sustituye verificar el flujo completo en el dispositivo con tu cuenta/MFA.

Verificado en este equipo: `flutter build apk --debug` terminó correctamente y generó `build/app/outputs/flutter-apk/app-debug.apk`. No se ejecutó el flujo completo en un dispositivo Android; el emulador Pixel_7 está instalado, pero no estaba iniciado durante la validación.
